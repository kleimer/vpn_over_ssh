# Changelog

Здесь фиксируются суть и причины изменений проекта. Новые записи — сверху.

## 2026-11-03 (мультисервер: профили и переключение)

### Добавлено

- **Несколько серверов на клиенте: `sshtun server add|list|use|del`.**
  Профили — файлы `~/sshtun/servers/<имя>.conf` (host/port/user/key/tun/mtu,
  комментарий через `--`). `server use <имя>` атомарно (tmp + mv) ставит
  профиль активным в привычный `~/sshtun/server.conf` (маркер
  `# sshtun-profile:`) и, если туннель работает, переподнимает его — под
  systemd через `systemctl restart`; если нет — профиль применится при
  следующем `up`. `server del` отказывает для активного профиля; повторный
  `use` идемпотентен. Маршрутная политика (exclude/include) от сервера
  не зависит и при переключении не сбрасывается.
- **Отображение активного профиля**: первая строка `sshtun status`
  («Профиль: …»), блок в `sshtun server list`; `server.conf`, созданный
  вручную/старым установщиком (без маркера), корректно показывается как
  «(server.conf без профиля)» — полная обратная совместимость.
- Установщик при install создаёт каталог `~/sshtun/servers/`; образец
  профиля — `examples/servers/example.conf`.

### Принятые решения

- Активный конфиг остался `server.conf` (а не симлинк): не ломается
  ни systemd-юнит, ни env-логика, ни существующие установки.
- Профили парсятся построчно (`KEY=VALUE`), файл не source'ится —
  профиль не может выполнить код от имени пользователя.
- env `SERVER_HOST` сохраняет высший приоритет; `server list`/`use`
  печатают предупреждение, если env перекрывает переключение профилей.
- Параллельная работа нескольких туннелей одновременно — вне объёма
  этого релиза (отдельная задача: per-server таблицы и tagged includes).


## 2026-11-02 (хотфикс: «сирота» и атомарная установка)

### Исправлено

- **Restart-цикл службы против «сироты» больше не жжёт сеть.**
  Суть: если супервизор умирает, не почистив за собой (ssh остаётся жив),
  служба с `Restart=always` входит в бесконечный цикл «VPN already running»,
  и КАЖДАЯ попытка (раз в ~7 с) заново качает списки AS/стран. Правка:
  `up` в обёртке проверяет «туннель уже жив» через state ДО ensure_autogen —
  отказ мгновенный, без сетевых операций. Цикл остаётся, но дешёвым;
  «сироту» убирает штатный `sshtun down`/`restart` (cgroup службы её
  зацепляет) либо `sshtun_pool_client.sh stop`.
- **Атомарная замена скриптов при install.**
  `install` в целевой файл обрезал его по месту; выполняющийся супервизор
  (bash читает скрипт инкрементально по смещению) получал бы битый
  байт-поток. Теперь: запись во временный файл + `mv` (rename) — работающий
  процесс держит старый inode, новые запуски видят новое содержимое.

## 2026-11-02 (хотфикс: SIGPIPE под pipefail)

### Исправлено

- **Молчаливое падение установщиков и клиента с exit 141 (SIGPIPE).**
  Суть: паттерны `ip ... | awk '{exit}'`, `ip ... | head -n1`,
  `getent | awk '{exit}'`, `sysctl | grep -q` — консьюмер завершается раньше,
  чем producer допишет вывод, producer получает SIGPIPE, а `pipefail` +
  `set -e` превращают это в мгновенную смерть скрипта без диагностики.
  На сервере проявилось как обрыв `install_server.sh` сразу после
  `Dependencies OK` (exit=141). Правка везде: вывод читается в переменную
  целиком, разбор — через herestring; проверки наличия алгоритма в ядре —
  подстрокой с границами слов вместо `grep -qx` в пайпе.
  Затронуты: install_server.sh (detect_wan_if/detect_wan_ip + проверка bbr),
  install_client.sh (setup_congestion_control), sshtun_full.sh
  (managed_sources, ensure_autogen, runtime-применение маршрутов),
  sshtun_pool_client.sh (resolve_server_ipv4, detect_default_route,
  install_lan_route, legacy-дочистка 0.0.0.0/1).

## 2026-11-02 (третий релиз дня)

### Добавлено

- **Опциональный выбор TCP congestion control (BBR/CUBIC) в установщиках.**
  Суть: туннель — один SSH/TCP-поток; на шумном пути клиент ↔ сервер
  стандартный CUBIC принимает случайные потери за перегрузку — обвал окна
  и RTO-спайки 300–500 мс у всего туннелированного трафика (head-of-line
  blocking). BBR замеряет ёмкость пути вместо реакции на потери — спайки
  снимаются. Включение строго по выбору:
  - `TCP_CONGESTION_CONTROL=bbr|cubic bash install_server.sh` и/или
    `... install_client.sh install`; по умолчанию (env не задан) система
    НЕ трогается;
  - bbr: загрузка модуля `tcp_bbr` + автозагрузка, sysctl-файл
    `/etc/sysctl.d/90-vpn-over-ssh-congestion.conf`;
  - откат: повторная установка с `=cubic` (клиентский uninstall также
    сносит файлы и возвращает cubic);
  - действует на НОВЫЕ TCP-соединения — после установки туннель надо
    переподнять (`sshtun restart`).
  Это sender-side алгоритм: полный эффект только при включении на обоих
  концах внешнего TCP. BBR линк не «чинит» — убирает то, что TCP добавляет
  поверх джиттера самого пути.
  Диагностика и замеры «до/после»: HOWTO.md, раздел 7.
  Причина: вечерний джиттер/потери на транзите до сервера превращались
  в многосотмиллисекундные всплески всего туннеля.

## 2026-11-02 (второй релиз дня)

### Добавлено

- **systemd-служба sshtun: досмотр туннеля и автостарт.**
  Суть: раньше `sshtun up` конфигурировал туннель и выходил, ssh-процесс
  оставался сиротой — после сна/падения сети туннель умирал до ручного
  вмешательства. Теперь:
  - клиент умеет `--foreground`: после старта досматривает ssh-процесс;
    неожиданная смерть ssh -> cleanup + exit 1, штатный stop -> exit 0;
  - обёртка в foreground-режиме делает `exec sudo` — main PID службы это
    sudo->клиент, поэтому systemd при `systemctl stop` ЖДЁТ, пока супервизор
    дочистит маршруты (без exec main-процесс умирал первым и systemd
    добивал остальных SIGKILL посреди cleanup — оставались таблица 200
    и правило 25100);
  - юнит `Restart=always` (внешний kill ЛЮБОГО звена цепочки — sudo relay'ит
  SIGTERM — раньше выглядел как штатный стоп без рестарта); явный
    `systemctl stop` systemd чтит и не перезапускает;
  - ручной `sshtun down`/`restart` при supervised-туннеле видит маркер
    `SUPERVISED=1` в state и идёт через `systemctl stop/restart` —
    иначе Restart=always перезапустил бы туннель;
  - grace-период 5 с закрывает гонку с внешним `stop_vpn` (state удаляется
    после cleanup, а не до);
  - блокировка (flock) отпускается перед supervise — иначе `down` никогда
    бы не получил лок.
  `install_client.sh` ставит выключенный юнит `/etc/systemd/system/sshtun.service`
  (`RestartSec=5`, `network-online.target`), автостарт — `systemctl enable sshtun`.
  Причина: туннель должен переживать сон ноутбука и любые внешние kill.
  Ограничение: для службы ключ без passphrase (SSH BatchMode).

### Изменено

- **Файлы AS/стран стали файлами-источниками (только токены).**
  Суть: раньше `excludes-as.txt`/`excludes-country.txt` после refresh
  превращались в тысячи строк префиксов, токен прятался в шапке. Теперь:
  - `~/sshtun/excludes-as.txt` / `excludes-country.txt` — только токены
    (`AS9009`, `ru`), правятся руками или fetch-командами; пользовательские
    комментарии сохраняются;
  - префиксы разворачиваются в `~/sshtun/generated/` — их читает клиент;
  - при `up` без сети: fallback на последний кэш в `generated/`
    (офлайн-миграция инлайн-префиксов из старого формата, если кэша нет);
  - `fetch-as`/`fetch-country` при сбое сети возвращают код 1 (не падают
    насмерть), чтобы `up` мог откатиться на кэш.
  Причина: блоки гуляют между странами и AS — список источников должен
  быть маленьким, читаемым и обновляться перекачкой, а не накоплением.

## 2026-11-02

### Изменено

- **Policy routing: маршруты переехали из main в отдельные таблицы
  (как Tailscale/Netbird).**
  Суть: раньше исключения и full-tunnel полутора default'а жили в
  main-таблице — `ip route` был нечитаемым (10k+ строк), а NetworkManager
  получал тысячи нотификаций на каждый add/del. Теперь:
  - table `POLICY_TABLE_DIRECT` (200) — вся политика: exclude-маршруты
    (direct), include-force (via tun), bypass /32 до сервера, копия
    connected-маршрута LAN;
  - table `POLICY_TABLE_TUN` (201) — только `0.0.0.0/1` + `128.0.0.0/1`;
  - `ip rule` pref 25100/25110 (до main 32766), приоритеты выбраны, чтобы
    не пересекаться с Tailscale (52xx) и Netbird (31xx);
  - main-таблица не трогается вообще; `down` делает flush таблиц + удаление
    правил (0.3 с вместо минут построчных del).
  Семантика префиксов сохранена полностью: exclude и include живут в ОДНОЙ
  таблице, LPM и «равный префикс → include (применён позже)» работают как
  раньше. Миграция: при первом `restart` после обновления state без
  маркера `POLICY_ROUTES` трактуется как старая схема и main дочищается
  построчно (одноразово).
  Причина: чистота main, отсутствие конфликтов с NetworkManager и другими
  VPN, читаемая диагностика (`ip route show table 200`).

### Исправлено

- **Критический баг с самого первого релиза: `stop`/`down`/`cleanup`
  никогда не видели списков маршрутов из state.**
  Суть: state загружается через `source` внутри функции, а строки
  `declare -p ARR` внутри функции создают ЛОКАЛЬНЫЕ переменные — массивы
  маршрутов терялись, cleanup снимал только 0.0.0.0/1 + 128.0.0.0/1 и
  bypass, per-prefix маршруты оставались в main навсегда (заметно только
  при смене шлюза). Правка: `declare` снимается sed'ом при загрузке —
  остаётся чистое глобальное присваивание. Одновременно найден и
  исправлен второй баг того же места: условие
  `[[ mode != del ]] && ! ip -force -batch` из-за short-circuit НИКОГДА
  не запускало сам батч для del — теперь батч запускается всегда,
  fallback только для add.

- **Старт туннеля с большими списками (страна, ~11k строк) занимал
  ~70 с вместо ~3 с.**
  Суть: две причины — `sed`-форк на каждую строку при парсинге
  route-файлов и `log`-вызов (fork `date`) на каждый маршрут в
  configure. Правка: чистка строк чистым bash, для списков длиннее
  `ROUTE_BATCH_THRESHOLD` — одна сводная строка лога. Итог: up ~3 с,
  down ~0.3 с со списком страны.

## 2026-11-01

### Добавлено

- **`sshtun_full.sh` — исключения целых AS и стран + force-список.**
  Суть: раньше исключения были только ручными CIDR в двух файлах. Теперь в
  `~/sshtun/` добавлены:
  - `excludes-as.txt` и `excludes-country.txt` — автогенерируемые файлы
    (помечены шапкой «не править вручную»; список источников хранится в
    `# sshtun-managed-sources:`);
  - `includes-force.txt` — принудительные маршруты «в туннель» с приоритетом
    над exclude-файлами.
  Новые команды обёртки:
  - `fetch-as AS... [--irr]` — префиксы автономных систем; по умолчанию из
    RIPEstat (фактически анонсируемые префиксы), `--irr` — через bgpq4
    (IRR-источники, могут быть устаревшими);
  - `fetch-country CC...` — префиксы стран по ISO-кодам из ipdeny.com
    (агрегированные, обновляются ежедневно);
  - `refresh` — перекачка всех автогенных списков по списку источников из
    шапок файлов;
  - `add` / `del` и `force-add` / `force-del` — управление пользовательским
    и force-списками (изменения применяются без перезапуска туннеля);
  - `list` — показ эффективной маршрутной политики.
  Источники в автогенных файлах объединяются между вызовами: повторный
  `fetch-as AS2` не затирает ранее добавленный `AS1`.
  Причина: ручное ведение исключений не масштабируется на AS/страны
  (например, «все сети РФ» — ~11k префиксов), а force-файл нужен для
  гарантированного заворота отдельных адресов в туннель даже при совпадении
  с exclude-списками.

- **`sshtun_pool_client.sh` — netlink-батчинг больших списков маршрутов.**
  Суть: списки маршрутов длиннее `ROUTE_BATCH_THRESHOLD` (по умолчанию 100)
  применяются и снимаются одной транзакцией `ip -force -batch` вместо
  посекундного цикла `ip route replace/del`. Списки уровня страны (10k+
  префиксов) добавляются и убираются за секунды. При ошибке батча —
  автоматический fallback на построчное применение.

### Изменено

- **Приоритет маршрутов в `sshtun_pool_client.sh`: exclude-списки теперь
  применяются раньше tunnel/force-роутов.**
  Суть: раньше на равных префиксах побеждал exclude (применялся позже).
  Теперь на равных префиксах tunnel/force-маршрут перекрывает exclude, что
  соответствует семантике force-файла. Более длинный префикс по-прежнему
  побеждает всегда (LPM ядра) — это осознанная семантика, задокументирована
  в README и выводе `list`.

### Исправлено

- **`sshtun_full.sh`: runtime-применение маршрутов никогда не срабатывало.**
  Суть: `tun_is_running()` проверял процесс SSH через `kill -0`, а процесс
  работает от root — обычный пользователь получает EPERM, функция всегда
  возвращала «туннель не работает», и `add`/`force-add` только писали файлы,
  откладывая маршруты до перезапуска. Баг был с момента появления `add`.
  Правка: проверка через `/proc/<pid>` (читается при стандартном hidepid),
  `kill -0` оставлен как fallback.

- **`sshtun_full.sh`: `del` / `force-del` молча обрывали скрипт при удалении
  последней строки файла.**
  Суть: `grep -vxF` при пустом результате возвращает rc=1, под `set -e`
  скрипт умирал после перезаписи файла, но до применения маршрутов.
  Правка: `|| true` на фильтрации.

- **Производительность сборки netlink-батчей.**
  Суть: построчный `printf ... >> "$batch"` в цикле на хостах с аудитом
  открытий файлов стоит ~7 мс на строку: батч из 5000 маршрутов собирался
  35 с против 0.1 с самого `ip -force -batch`. Правка: один редирект на
  весь цикл в обоих скриптах. Итог: 5000 маршрутов добавляются/снимаются
  за ~0.2 с.

### Добавлено (вторая партия, установка и полировка)

- **`install_client.sh` — установщик Linux-клиента.**
  Суть: раньше клиент запускался прямо из репозитория. Теперь
  `install_client.sh install` копирует `sshtun_full.sh` и
  `sshtun_pool_client.sh` в `/opt/sshtun_client/`, создаёт symlink
  `/usr/local/bin/sshtun` и при первой установке заполняет `~/sshtun/`
  шаблонами из `examples/` (существующие файлы не трогает). Команды:
  `install` / `update` (git pull + install) / `reinstall` /
  `uninstall [--purge]`. Обёртка умеет резолвить свой путь через symlink
  (`readlink`-цепочка), поэтому работает и из `/usr/local/bin`.

- **`fetch-as --remove AS...` и `fetch-country --remove CC...`.**
  Суть: раньше автогенные списки можно было только пополнять — убрать AS
  или страну можно было ручной правкой. Теперь источник исключается,
  оставшиеся перекачиваются, файл с пустым списком источников удаляется,
  а ставшие лишними маршруты снимаются через netlink-батч.

- **`docs/HOWTO.md`** — пошаговая инструкция по тестированию: исключения,
  force-семантика (LPM и равные префиксы), AS/страны в изолированном
  каталоге, живое применение диффов, установщик, изолированный тест
  производительности батча, чек-лист перед тегом.

### Изменено (команды после тестирования)

- **Явные подкоманды вместо двусмысленных `add`/`del`/`force-add`/`force-del`.**
  Суть: по команде `sshtun add` было непонятно, куда попадёт CIDR —
  в исключения или в force-список. Теперь:
  - `sshtun exclude add|del CIDR...` — исключения (напрямую, мимо туннеля);
  - `sshtun include add|del CIDR...` — принудительно в туннель.
  Старые формы сохранены как алиасы: работают, но выводят подсказку
  миграции. Синтаксис обновлён в README, `docs/HOWTO.md`, шаблонах
  `examples/` и шапке установленного файла `~/sshtun/excludes-custom.txt`.

- **Токены-источники прямо в автогенных файлах.**
  Суть: раньше `excludes-as.txt` / `excludes-country.txt` могли содержать
  только готовые префиксы — источники задавались исключительно командами
  `fetch-as` / `fetch-country`. Теперь в тело файлов можно вручную
  дописывать `AS9009` или `ru` — `refresh` (и автоматически `up` перед
  стартом клиента) развернёт токены в префиксы. `refresh` собирает
  источники из обоих файлов и распределяет по форме токена (ASnnnn →
  RIPEstat/bgpq4, иначе → ipdeny), так что перепутанный файл не ломает
  обновление. `fetch-as --remove` / `fetch-country --remove` убирают и
  такие ручные токены — они не воскресают при следующем refresh.

- **Комментарии к записям exclude/include.**
  Суть: `sshtun exclude add 178.62.9.171 -- мой дроплет в DigitalOcean`
  (то же для `include add`). Комментарий пишется в строку файла после `#`;
  клиент такие строки уже умел парсить (отрезает `#`-часть), поэтому
  формат совместим со стартом туннеля. Дедупликация и удаление работают
  по первому токену строки, комментарий не мешает; повторный `add` с
  комментарием обновляет его. `sshtun list` показывает записи с
  комментариями. В автогенных файлах комментарии не живут — их
  перезаписывает `refresh`.

### Исправлено (вторая партия)

- **Двойной запуск netlink-батча в runtime-применении обёртки.**
  Суть: конструкция `if ! cmd; then ...; else cmd; fi` запускала
  `ip -force -batch` дважды; повторный прогон по уже удалённым маршрутам
  с via-шлюзом стоил миллисекунды на строку в ядре — дифф из 4422
  удалений занимал 30 с вместо 0.5 с. Правка: батч запускается ровно
  один раз, WARNING по коду возврата.

- **fork-grep на каждый CIDR при массовом снятии маршрутов.**
  Суть: `del` внутри `apply_direct_changes` проверял наличие CIDR в
  других exclude-файлах через grep-вызовы: тысячи CIDR × 4 файла = десятки
  тысяч процессов. Правка: множество exclude-CIDR загружается один раз в
  ассоциативный массив (`load_exclude_set`).

## 2026-10-27

### Исправлено

- **`install_server.sh` — установка падала на OpenSSH старше 7.8.**
  Суть: в генерируемый `sshd_config` жёстко входили директивы `PermitListen none`
  и `PermitOpen none`. `PermitListen` появилась только в OpenSSH 7.8, поэтому
  `sshd -t` завершался с ошибкой `Bad configuration option`, а из-за `set -e`
  весь установщик прерывался. Проявление: Ubuntu 18.04 с OpenSSH 7.6p1.
  Правка: обе директивы вынесены из heredoc-конфига в `try_add_sshd_directive()`
  (тот же механизм, что уже использовался для `UnusedConnectionTimeout`) —
  неподдерживаемые данной версией sshd директивы теперь пропускаются с записью
  в лог. Поведение на новых OpenSSH не изменилось; на старых форвардинг
  по-прежнему закрыт через `AllowTcpForwarding no` и `ForceCommand /bin/false`,
  то есть на безопасность это не влияет.

### Добавлено

- **`sshtun_full.sh` — обёртка «full tunnel + исключения» над `sshtun_pool_client.sh`.**
  Суть: один скрипт для постоянного режима «весь трафик через сервер, кроме
  списка исключений». Команды `up` / `down` / `restart` / `status` / `doctor` /
  `cleanup`; два repeatable `--exclude-file` — базовый `~/sshtun/excludes.txt`
  (RFC1918 и админские сети) и пополняемый `~/sshtun/excludes-custom.txt`;
  команда `add CIDR...` дописывает исключение в файл и, если туннель поднят,
  сразу ставит direct-маршрут без перезапуска. Одиночные адреса принимает
  без `/32` (подставляет сама). Параметры подключения (хост, порт, ключ,
  пул tun, MTU) — переменные в шапке скрипта.
