# Changelog

Здесь фиксируются суть и причины изменений проекта. Новые записи — сверху.

## 2026-11-01

### Добавлено

- **`sshtun_full.sh` — исключения целых AS и стран + force-список.**
  Суть: раньше исключения были только ручными CIDR в двух файлах. Теперь в
  `~/sshtun/` добавлены:
  - `excludes-as.txt` и `excludes-country.txt` — автогенерируемые файлы
    (помечены шапкой «не править вручную»; список источников хранится в
    `# sshtun-managed-sources:`);
  - `includes-force.txt` — принудительные маршруты «в туннель» с приоритетом
    над exclude-файлами.
  Новые команды обёртки:
  - `fetch-as AS... [--irr]` — префиксы автономных систем; по умолчанию из
    RIPEstat (фактически анонсируемые префиксы), `--irr` — через bgpq4
    (IRR-источники, могут быть устаревшими);
  - `fetch-country CC...` — префиксы стран по ISO-кодам из ipdeny.com
    (агрегированные, обновляются ежедневно);
  - `refresh` — перекачка всех автогенных списков по списку источников из
    шапок файлов;
  - `add` / `del` и `force-add` / `force-del` — управление пользовательским
    и force-списками (изменения применяются без перезапуска туннеля);
  - `list` — показ эффективной маршрутной политики.
  Источники в автогенных файлах объединяются между вызовами: повторный
  `fetch-as AS2` не затирает ранее добавленный `AS1`.
  Причина: ручное ведение исключений не масштабируется на AS/страны
  (например, «все сети РФ» — ~11k префиксов), а force-файл нужен для
  гарантированного заворота отдельных адресов в туннель даже при совпадении
  с exclude-списками.

- **`sshtun_pool_client.sh` — netlink-батчинг больших списков маршрутов.**
  Суть: списки маршрутов длиннее `ROUTE_BATCH_THRESHOLD` (по умолчанию 100)
  применяются и снимаются одной транзакцией `ip -force -batch` вместо
  посекундного цикла `ip route replace/del`. Списки уровня страны (10k+
  префиксов) добавляются и убираются за секунды. При ошибке батча —
  автоматический fallback на построчное применение.

### Изменено

- **Приоритет маршрутов в `sshtun_pool_client.sh`: exclude-списки теперь
  применяются раньше tunnel/force-роутов.**
  Суть: раньше на равных префиксах побеждал exclude (применялся позже).
  Теперь на равных префиксах tunnel/force-маршрут перекрывает exclude, что
  соответствует семантике force-файла. Более длинный префикс по-прежнему
  побеждает всегда (LPM ядра) — это осознанная семантика, задокументирована
  в README и выводе `list`.

### Исправлено

- **`sshtun_full.sh`: runtime-применение маршрутов никогда не срабатывало.**
  Суть: `tun_is_running()` проверял процесс SSH через `kill -0`, а процесс
  работает от root — обычный пользователь получает EPERM, функция всегда
  возвращала «туннель не работает», и `add`/`force-add` только писали файлы,
  откладывая маршруты до перезапуска. Баг был с момента появления `add`.
  Правка: проверка через `/proc/<pid>` (читается при стандартном hidepid),
  `kill -0` оставлен как fallback.

- **`sshtun_full.sh`: `del` / `force-del` молча обрывали скрипт при удалении
  последней строки файла.**
  Суть: `grep -vxF` при пустом результате возвращает rc=1, под `set -e`
  скрипт умирал после перезаписи файла, но до применения маршрутов.
  Правка: `|| true` на фильтрации.

- **Производительность сборки netlink-батчей.**
  Суть: построчный `printf ... >> "$batch"` в цикле на хостах с аудитом
  открытий файлов стоит ~7 мс на строку: батч из 5000 маршрутов собирался
  35 с против 0.1 с самого `ip -force -batch`. Правка: один редирект на
  весь цикл в обоих скриптах. Итог: 5000 маршрутов добавляются/снимаются
  за ~0.2 с.

### Планы

- **GUI-оболочка (Linux/macOS) — следующий релиз.**
  Старт/стоп туннеля, статус, просмотр логов и конфигов, вызов редактора.
  Текущие изменения сначала тестируются и фиксируются тегом.

### Добавлено (вторая партия, установка и полировка)

- **`install_client.sh` — установщик Linux-клиента.**
  Суть: раньше клиент запускался прямо из репозитория. Теперь
  `install_client.sh install` копирует `sshtun_full.sh` и
  `sshtun_pool_client.sh` в `/opt/sshtun_client/`, создаёт symlink
  `/usr/local/bin/sshtun` и при первой установке заполняет `~/sshtun/`
  шаблонами из `examples/` (существующие файлы не трогает). Команды:
  `install` / `update` (git pull + install) / `reinstall` /
  `uninstall [--purge]`. Обёртка умеет резолвить свой путь через symlink
  (`readlink`-цепочка), поэтому работает и из `/usr/local/bin`.

- **`fetch-as --remove AS...` и `fetch-country --remove CC...`.**
  Суть: раньше автогенные списки можно было только пополнять — убрать AS
  или страну можно было ручной правкой. Теперь источник исключается,
  оставшиеся перекачиваются, файл с пустым списком источников удаляется,
  а ставшие лишними маршруты снимаются через netlink-батч.

- **`docs/HOWTO.md`** — пошаговая инструкция по тестированию: исключения,
  force-семантика (LPM и равные префиксы), AS/страны в изолированном
  каталоге, живое применение диффов, установщик, изолированный тест
  производительности батча, чек-лист перед тегом.

### Исправлено (вторая партия)

- **Двойной запуск netlink-батча в runtime-применении обёртки.**
  Суть: конструкция `if ! cmd; then ...; else cmd; fi` запускала
  `ip -force -batch` дважды; повторный прогон по уже удалённым маршрутам
  с via-шлюзом стоил миллисекунды на строку в ядре — дифф из 4422
  удалений занимал 30 с вместо 0.5 с. Правка: батч запускается ровно
  один раз, WARNING по коду возврата.

- **fork-grep на каждый CIDR при массовом снятии маршрутов.**
  Суть: `del` внутри `apply_direct_changes` проверял наличие CIDR в
  других exclude-файлах через grep-вызовы: тысячи CIDR × 4 файла = десятки
  тысяч процессов. Правка: множество exclude-CIDR загружается один раз в
  ассоциативный массив (`load_exclude_set`).

## 2026-10-27

### Исправлено

- **`install_server.sh` — установка падала на OpenSSH старше 7.8.**
  Суть: в генерируемый `sshd_config` жёстко входили директивы `PermitListen none`
  и `PermitOpen none`. `PermitListen` появилась только в OpenSSH 7.8, поэтому
  `sshd -t` завершался с ошибкой `Bad configuration option`, а из-за `set -e`
  весь установщик прерывался. Проявление: Ubuntu 18.04 с OpenSSH 7.6p1.
  Правка: обе директивы вынесены из heredoc-конфига в `try_add_sshd_directive()`
  (тот же механизм, что уже использовался для `UnusedConnectionTimeout`) —
  неподдерживаемые данной версией sshd директивы теперь пропускаются с записью
  в лог. Поведение на новых OpenSSH не изменилось; на старых форвардинг
  по-прежнему закрыт через `AllowTcpForwarding no` и `ForceCommand /bin/false`,
  то есть на безопасность это не влияет.

### Добавлено

- **`sshtun_full.sh` — обёртка «full tunnel + исключения» над `sshtun_pool_client.sh`.**
  Суть: один скрипт для постоянного режима «весь трафик через сервер, кроме
  списка исключений». Команды `up` / `down` / `restart` / `status` / `doctor` /
  `cleanup`; два repeatable `--exclude-file` — базовый `~/sshtun/excludes.txt`
  (RFC1918 и админские сети) и пополняемый `~/sshtun/excludes-custom.txt`;
  команда `add CIDR...` дописывает исключение в файл и, если туннель поднят,
  сразу ставит direct-маршрут без перезапуска. Одиночные адреса принимает
  без `/32` (подставляет сама). Параметры подключения (хост, порт, ключ,
  пул tun, MTU) — переменные в шапке скрипта.
